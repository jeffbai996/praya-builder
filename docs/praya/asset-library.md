# Object and custom-head library — requested capability

Source: direct user direction, 2026-09-08, S1 in sources.md; [interior reference](../reference-images/2026-09-08_03.35.27.png).

## Accepted direction

Combine inventive ordinary-block assemblies with custom player heads for recognisable small objects. Reuse the existing City Hall head collection and allow discovery of new heads. The user specifically identified a wall-block computer, an Xbox and Microsoft bags. Do not force every object into one representation.

## Proposed implementation sequence — not delivered

1. Identify the actual player-head plugin/database and locate the collection within Oakville City Hall. Inventory existing assets read-only, with names, visual previews, source IDs, texture/profile data and provenance where available.
2. Provide an object library searchable by purpose: computers, consoles, bags and other furnishings. Separate existing collected assets from newly discovered candidates.
3. Give assemblies semantic names, dimensions, orientation/attachment requirements and applicable uses. Prefer an existing suitable asset; use block assemblies where they give a better silhouette or fit.
4. Extend the plan/compiler, renderer and schematic/placement pipeline to retain custom-head profile/texture data. Resolve sign-text support alongside other explicitly supported block-entity types. Do not remove the survey protection of arbitrary block entities to achieve this.
5. Verify that preview, exported schematic and isolated in-game readback agree on the selected asset, rotation and texture. A generic player-head block or browser-only decoration is not equivalent.
6. For new external assets, identify the real provider and its retrieval mechanism/terms first, record stable source identifiers, and distinguish an imported candidate from an accepted collection item.
