# Site-aware design and isolated construction

Build 20260906.03 provides `/studio` alongside the existing catalogue review. It uses
the existing Java compiler and block renderer. Designs are generated by authored
assemblies or supplied structured plans; no model-provider calls are made.

## Operator workflow

1. Open `/studio` directly. No login, workspace key or session setup is required.
2. Import a Sponge v3 `.schem` and its metadata, or create a flat/sloping synthetic
   fixture. Source coordinates, plot bounds, frontage and protected volumes are
   explicit. Survey metadata and states are immutable after import.
3. Create three apartment studies, start from a catalogue revision, or upload a
   structured plan. The studies have paired, staggered and L-shaped arrangements,
   six apartments, private bathrooms, shared stairs and accessible roof gardens.
4. Select a component in the model or selector. Change a material role, switch a
   study roof between sheltered/open, or download a targeted request and context
   for an external design agent. Upload the revised plan to compile it.
5. Inspect all elevations, floor cutaways, geometry diagnostics and the exact
   baseline difference. Undo/redo remains local to the saved draft history.
   Save creates an immutable revision record. Existing catalogue files are never
   rewritten by these operations.
6. For the configured isolated world, preview placement after saving the exact
   revision. Review the world, artifact fingerprint and changed-cell count, then
   explicitly apply. Pause, reconcile and preview rollback are separate actions.

Import metadata uses this shape (bounds are half-open world coordinates):

```json
{"name":"Example plot","world":"builder-isolated","origin":[0,60,0],"capturedAt":"2026-09-06T00:00:00Z","plot":{"min":[0,60,0],"max":[32,92,32]},"frontage":[16,61,1],"protected":[{"min":[0,60,0],"max":[32,61,2]}]}
```

The manifest origin is the imported volume's minimum corner; schematic offsets
do not override it. Empty cells inside the volume are known air. Outside it is
unknown. The importer bounds compressed bytes (8 MiB), expanded NBT (16 MiB),
depth, collection sizes, palette indices and survey volume (262,144 cells, each
axis at most 128). Every palette state must resolve against the pinned 1.21.4
registry. Newer source data versions are retained with an explicit compatibility
notice; no data migration or block-entity import is performed.

## Common agent interface

The [Praya map connection](praya-map-connection.md) documents the live map handoff,
guided survey capture and saved placement-package contract.

Use `node preview/workspace-cli.cjs <operation> [request.json]`. Override the base
address with `BUILDER_WORKSPACE_URL`. No credentials are required. The same
operations are available under `/api/workspace/`; writes require the
`X-Builder-Write: 1` header, supplied automatically by the CLI and studio.

| Operation | Method and input |
| --- | --- |
| `context` | GET: surveys, drafts, revisions and limits |
| `capture/status` | GET: exact connected world, reserved bounds and survey capability |
| `capture/selection` | POST: create a selection covering the connected reserved area |
| `selections/{id}/capture` | POST: begin a bounded, durable survey capture |
| `captures/{id}` | GET: read/verification progress, terminal result and published site ID |
| `captures/{id}/cancel` | POST: cancel future reads without publishing a partial survey |
| `sites` | POST: `schematic` as base64 and `metadata` |
| `sites/{id}` | GET: exact immutable survey |
| `drafts` | POST: `plan` or `catalogue`, optional `parentHash`, `siteId`, `transform`, `brief` |
| `drafts/{id}/context` | GET: brief, plan, identities, site summary, highest-non-air columns and diagnostics |
| `drafts/{id}/edit` | POST: `expectedVersion`, full `plan` or `palette` patch, optional `componentId` |
| `drafts/{id}/edit` | POST: `expectedVersion`, roof `componentId`, `variant: {name: "roof-canopy", value: "open" or "sheltered"}` |
| `drafts/{id}/history` | POST: `expectedVersion`, `direction: "undo" or "redo"` |
| `drafts/{id}/diff` | GET: owned-cell changes from the baseline |
| `drafts/{id}/request` | POST: `expectedVersion`, `componentId`, `instruction` |
| `drafts/{id}/save` | POST: `expectedVersion`, `candidateHash`, `idempotencyKey` |
| `construction/status` | GET: isolated connection and reserved world |
| `construction/prepare` | POST: `draftId`, `artifactHash`, `idempotencyKey` |
| `construction/jobs/{id}` | GET: durable progress and observations |
| `construction/jobs/{id}/apply` | POST: exact `changeHash` |
| `construction/jobs/{id}/pause` | POST: stop future batches |
| `construction/jobs/{id}/reconcile` | POST: inspect uncertain progress before reapplication |
| `construction/jobs/{id}/rollback` | POST: prepare a reverse job, retaining conflicting later edits |

Transforms contain an integer `origin: [x,y,z]` and `turns: 0..3`. Position and
rotation are chosen when starting a draft. Changing an existing draft's site or
transform requires starting another draft; it cannot quietly retarget an approval.
Drafts have a version distinct from plan revision labels. Immutable saved-record
IDs distinguish accepted successors, and their parent hashes preserve lineage.

Compilation is serialized, with at most four pending requests, a 30-second
runtime limit and the existing 10,000-cell plan ceiling. Invalid candidates
retain the prior render but cannot be saved. Version conflicts return 409.
Save idempotency keys cannot be reused for different artifacts.

The walking check uses a conservative grid, two-block headroom, one-block steps
and openable doors. It checks reachability from the confirmed street connection.
It does not simulate Minecraft player physics or establish architectural quality.
Source context omits the full raw block array by default; exact survey retrieval
is a separate operation. Any external agent can use this contract. Future smaller
and frontier models should share it and remain explicitly selectable.

## Storage and construction boundaries

The single-operator service stores versioned JSON records and content-addressed
artifacts beneath `BUILDER_WORKSPACE_DIR`. Publication uses fsync and atomic
replacement; records are capped at 64 MiB and the workspace at 512 MiB. A process lock enforces one writer. Back up that directory separately from
the repository. No database driver or provider dependency is introduced.
The directory is never served as static content. Writes require a custom header;
requests supplying an Origin must match an exact allowed origin. Browser and CLI
requests use the same handlers without authentication. The legacy player command
remains separate.

The Paper adapter is disabled unless `BUILDER_TEST_BRIDGE=1`. Its configuration
requires `BUILDER_BRIDGE_TOKEN`, `BUILDER_TEST_WORLD`, `BUILDER_TEST_MIN` and
`BUILDER_TEST_MAX`; `BUILDER_BRIDGE_PORT` defaults to 8094. The preview uses
`BUILDER_BRIDGE_URL` and the same token. The adapter binds loopback, checks the
world UUID, reserves one bounded plot and exposes only status/read/survey/validate/batch.
Set `BUILDER_BRIDGE_READ_ONLY=1` on a survey-only deployment. That mode rejects
validation and placement routes, advertises `placement: 0`, and only preloads
already generated chunks. It never changes the random-tick game rule. Studio can
use separate `BUILDER_SURVEY_URL` and `BUILDER_SURVEY_TOKEN` settings; when omitted,
capture uses the existing construction connection. A remote survey adapter needs
a managed loopback forward with its own SSH connection, independent of shared
interactive control sockets. Check both Windows and WSL listeners when choosing
ports on mirrored-network hosts.
It never accepts console commands. The optional `BUILDER_TEST_PRELOAD=1` explicitly
loads and tickets only the reserved test chunks; normal requests never generate
chunks implicitly. The opt-in disposable fixture also uses `BUILDER_TEST_FREEZE_RANDOM_TICKS=1` with preload to set random tick speed to zero. This makes repeat trials reproducible; normal gameplay can otherwise alter surveyed blocks independently of the paste.

Each WorldEdit batch has at most 128 cells and a cooperative 4 ms submission
target, including flush time in its measured result. Side effects are disabled;
the tested material allowlist excludes fluids, falling blocks, active machinery
and block-entity contents. A long flush can exceed the target. Game reads and
writes run on the server thread; HTTP, persistence and job orchestration do not.

The compiled mask is authoritative: missing cells remain untouched; explicit air
clears. Preflight checks the current target against the survey, then every batch
rechecks its before states. A durable intent precedes each batch. Restarted jobs
pause instead of replaying automatically. Readback records observed states.
Rollback restores only cells still matching their intended post-edit state and
reports conflicts. Equal-state comparison cannot establish ownership if someone
changed a block away and back. Physics/plugin side effects and arbitrary live
world rollback are not certified by this isolated trial.

## Verification

Automatic survey jobs read at most 128 cells per server-thread batch, then read
the entire volume again and compare block states and block-entity locations.
Only matching complete reads publish an immutable site. This detects changes
observed between passes; it is not an atomic snapshot, and construction still
checks current blocks. Restart interrupts unfinished captures; capture records
and batch evidence remain durable. A cancelled, failed or interrupted capture
does not replace an existing survey or draft. Capture and construction cannot
run concurrently through this service.

Surveys bind world UUID, origin, dimensions, selection, timestamps, source data
version and hashes. Block entities are protected automatically because their
contents are not imported. Unknown block states fail validation against the
pinned registry rather than being silently substituted. Street entrance height
is derived from the surveyed column when marked in the plot editor; review the
result if that column contains a tree, structure or fluid.

Selections may add `contextMargin` (0–16 blocks) around the buildable plot. The
complete capture must still fit the reserved area and survey budget. The plot
stays smaller than the survey; context never grants permission to build outside
it. WorldEdit fallback commands capture the surrounding volume as well.

`GET sites/{id}/mesh?depth=surface` provides a display slice with three blocks
below the lowest nonempty surface column. Omit the parameter or use `depth=full`
for the full survey mesh. The immutable site, hashes, assessments and placement
checks always use the full captured data. Studio defaults to the surface view
and exposes a **Full survey depth** toggle. Saved site links use `/studio?site=ID`.

`preview/check-capture.cjs` covers publication, changed terrain, interrupted and
cancelled reads, invalid responses, world/bounds mismatch, headroom, admission
serialization and final-record recovery. `preview/check-studio-capture.cjs`
exercises the actual isolated Paper connection, cancellation, completed survey,
reload/history and desktop/mobile rendering. It requires a fresh candidate
workspace, the configured disposable bridge and the existing browser runtime.

`tests/test_design_service.py` runs the pure site/draft/job contracts and the
flat/sloping architectural fixtures. `preview/check-studio.cjs` verifies served
authoring, scoped preservation, history, persistence, credential-free access, origin checks, themes and
mobile layout. `preview/check-paper-placement.cjs` is an explicit opt-in test that
writes through the reserved disposable Paper bridge, verifies exact states and
tests conflict-aware rollback. Do not run it against a production world.

The full milestone still requires a user-selected real-world extract and actual
player walkthrough. Synthetic surveys and grid checks are not substitutes for
those acceptance steps. Neighborhood generation and integrated model calls remain
later stages.
